THE LEARNING MOMENT

Ask for context, not just commands

A command can be technically reasonable and still be a poor teaching tool. In our classroom test, an early diagnostic script stopped when Python was missing, so the tool designed to create evidence failed at the exact moment evidence mattered most.

The better design treats a missing tool as diagnostic information. It records what worked, clearly labels what did not, preserves the result, and explains what each observation means.

1. Preserve the state

Capture timestamp, Windows and PowerShell information, Python, Git, and the other approved checks before changing anything.

2. Fail helpfully

A missing tool should appear as NOT FOUND or a stable diagnostic code. It should not erase the rest of the evidence or trigger an improvised repair.

3. Explain the evidence

A useful receipt says what was observed, why it matters, where the artifact was saved, and how to open or share it safely.

Privacy note: diagnostic receipts may contain your Windows username or computer name. That is useful for classroom troubleshooting, but review a receipt before posting it publicly.

WHEN YOU ASK AI FOR HELP

Give the model the job, the boundary, and the evidence

Do not settle for “give me a PowerShell command.” Better prompts describe the environment, the goal, what must not change, how failures should behave, and what evidence you want back.

Prompt pattern
I am in Windows PowerShell in a managed classroom lab. Help me interpret the supplied Week 2 Local AI Lab result. Do not tell me to install software, change PATH or security settings, use admin rights, enter credentials, download another model, or repair the managed machine. Preserve the evidence I already have. Explain what each result proves, what it does not prove, and the next approved step. If something is missing or fails, treat that as diagnostic evidence and tell me exactly what result or W2 code to bring to my instructor.

When you are asking AI to create a diagnostic artifact, also specify the output you want: save a receipt, make it readable, explain every field, tell me where the file is, and tell me how to open it. That extra context turns a command dump into a tool you can actually learn from.

EVIDENCE, NOT GUESSING

What does this result prove?

READY means the supplied readiness path completed successfully. NOT READY means exit code 2 and a stable diagnostic code such as W2-API-001 or W2-MODEL-001. Record the first code; do not guess at a repair.

A receipt is a snapshot, not a prophecy. A passing observation proves that layer worked at that moment. A missing Python executable proves Python was not available through the checked path; it does not by itself prove why.

The check does not prove that a later generated answer is correct. Review the requested scope, git diff, and independent test result before accepting a change. Aider proposes. Git testifies. You decide.
